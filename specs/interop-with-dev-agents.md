# AJ-74 — Interop with code agents

> Tracked in [`board.json`](../board.json). Type=feature, priority=p1,
> milestone=v0.1.x.

## What

Make every Ajolopy app a **first-class citizen for code agents** —
Claude Code, opencode, Cursor, Cline, Aider, GitHub Copilot, Windsurf,
Continue, Roo, Zed AI, and anything that joins the ecosystem next.
The wedge user opens the scaffolded repo in their agent of choice and
that agent already knows:

1. How the project is laid out and which primitives it uses.
2. What `ajolopy` CLI commands exist (`eval`, `deploy`, `doctor`,
   `env:*`, `generate`).
3. Which `@Tool`s the app exposes over MCP so the agent can call them.
4. How to run the test / eval / type-check gates before suggesting an
   edit.

Today only the Ajolopy repo itself ships these artefacts (`AGENTS.md`,
`@MCPServer`). Scaffolded apps generated by `ajolopy new` ship none of
them, so dev agents start cold.

## Why p1

A growing share of v0.1's target users (AI Engineer at Series-A
startups) already drive their daily edits through Claude Code /
Cursor / opencode. If `ajolopy new` produces a repo that any code
agent can pick up and be productive in, the framework gets the
multiplier of the agent's leverage for free. If it produces a bare
repo, the user spends 30 minutes hand-writing instructions for their
agent — which is exactly the integration-tax tax v0.1 set out to
remove.

## Scope

### 1. `ajolopy new` emits agent-discovery artefacts

The scaffold generator (under `src/ajolopy/templates/`) gains a new
`agents/` module that emits:

| File                                  | Purpose                                                                                                             |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `AGENTS.md`                           | Cross-agent universal entry point. Includes build/test/eval/deploy commands, conventions, primitives, file layout.  |
| `.mcp.json`                           | Declares the app's own `@MCPServer` so MCP-aware agents discover its tools on open.                                 |
| `.claude/commands/*.md`               | Claude Code slash commands: `/ajolopy-eval`, `/ajolopy-deploy`, `/ajolopy-doctor`, `/ajolopy-new-agent`.             |
| `.opencode/commands/*.md`             | Same slash commands in opencode's frontmatter format.                                                               |
| `.cursor/rules/ajolopy.mdc`           | Cursor project rules in `.mdc` format pointing at `AGENTS.md`.                                                      |
| `.windsurfrules`                      | Windsurf single-file rules pointing at `AGENTS.md`.                                                                 |
| `.github/copilot-instructions.md`     | GitHub Copilot instructions pointing at `AGENTS.md`.                                                                |
| `.continue/config.json` augmentation  | Continue.dev rule pointing at `AGENTS.md` (skipped if user already has one).                                        |

The `AGENTS.md` is the **source of truth**; the per-agent files are
thin pointers ("read `AGENTS.md`") plus tool-specific quirks. When the
AGENTS.md updates, the pointers don't.

### 2. Wizard question

`ajolopy new` asks one new question (multi-select):

> Which code agents should the scaffold target? (Space-select, Enter
> to confirm. AGENTS.md is always written; this controls the per-agent
> dotfiles.)
>
> [x] Claude Code · `.claude/commands/`, `.mcp.json`
> [x] opencode · `.opencode/commands/`, `.mcp.json`
> [ ] Cursor · `.cursor/rules/ajolopy.mdc`
> [ ] Windsurf · `.windsurfrules`
> [ ] GitHub Copilot · `.github/copilot-instructions.md`
> [ ] Continue.dev · `.continue/config.json`
> [ ] All

Default: Claude Code + opencode (the two CLI-first agents whose
ecosystem most closely overlaps with v0.1's wedge user).

### 3. Docs page

New page at `docs/guides/code-agents.md` (linked from the docs nav)
covering:

- What AGENTS.md is and why every code agent reads some flavour of it.
- The cross-agent convention (https://agents.md/) and how Ajolopy
  follows it.
- How `@MCPServer` lets any MCP-aware agent call the app's `@Tool`s.
- A worked example: open the support-agent example in Claude Code →
  the agent reads `AGENTS.md` → invokes `ajolopy eval --ci` → modifies
  the agent's system prompt → re-runs the eval. End-to-end loop.

### 4. Banner in `examples/*/README.md`

A two-line banner added to the top of each example README:

> **Works with Claude Code, opencode, Cursor, Cline, Aider, Windsurf,
> Copilot, Continue, Zed AI, Roo —** the scaffold ships `AGENTS.md`
> plus per-agent dotfiles so any code agent picks up the project's
> conventions on open.

### 5. Repo-level dogfooding

Apply the same emission to the framework repo itself: confirm
`AGENTS.md` is up to date (it is — 10 KB, used for our own workflow),
add the same per-agent dotfiles (`.cursor/rules/`,
`.windsurfrules`, `.github/copilot-instructions.md`) pointing at
`AGENTS.md`. We already use `.claude/` directly; add the others for
consistency.

## Out of scope

- A new `@Agent` decorator subclass for "dev agents" (CLI/TUI agents
  with file-edit + bash). That would be interpretation A (Ajolopy as
  framework for *building* dev agents) and is v0.2+ territory.
- Adopting agent-side features as primitives (`@Plan`, `@Subagent`,
  `@Hook`, `@Command`). Locked surface stays at 10 primitives.
- Cross-agent slash command standardisation. The format-per-tool
  divergence is a real cost, but it's not Ajolopy's problem to solve
  — we emit what each tool reads today.
- Vendor-specific MCP transports beyond the standard MCP stdio /
  HTTP+SSE transports the framework already supports.

## Implementation notes

- Reuse the wizard question machinery already present for Memory /
  RAG backend selection (look at `src/ajolopy/cli/new.py`).
- The per-agent dotfiles should be small templates living under
  `src/ajolopy/templates/code_agents/` — one file per agent, written
  in Jinja-light string-format so the rendered AGENTS.md / project
  paths interpolate cleanly.
- For the `AGENTS.md` content: synthesise from the wizard answers
  (which primitives are wired, which providers, which Memory backend)
  rather than ship a single hard-coded template. Stale instructions
  are worse than no instructions.
- `.mcp.json` schema: follow the Anthropic-published schema for Claude
  Code's `.mcp.json`. opencode and Cursor accept the same format.
